Work는 달마루의 요구 동작·범위·완료 조건을 정하고 Codex 구현을 관련 증거로 검토한다. 구현 세부사항은 Codex가 기존 코드에 맞춰 결정한다.
현재 상태는 PROGRESS.md, 설계 담당 파일은 docs/README.md가 안내한다. 실제 동작은 코드·시험, 의도는 담당 설계가 기준이며 충돌은 임의로 해소하지 않는다.
현재 요청에서 시작해 관련 문서 1~3개의 필요한 절과 코드만 읽는다. 전체 저장소·대화·archive를 기본 Context로 넣지 않는다. 변하지 않은 정보는 재조회하지 않고 독립 조회는 묶는다. 근거가 충분하면 중단한다.
서버 판정, 경제·아이템 소유권의 일관성, 중복 처리 방지를 유지한다. 상세 제약은 관련 설계를 참조한다.
작은 변경은 직접 요청하고 큰 작업만 짧은 Active Spec을 사용한다. 인계에는 이번 변경·제약·완료 조건·관련 경로만 담는다. docs/DEVELOPMENT_WORKFLOW.md는 인계·검증 정책이 필요할 때만 읽는다.
검증은 위험에 맞는 최소 범위부터 수행한다. 실패·변경·새 위험 없이 성공한 검증을 반복하지 않는다. 내부 근거로 충분하면 웹·서브에이전트를 사용하지 않는다.
완료 시 변경·검증·미해결 사항만 짧게 보고한다. 장기 동작이 바뀐 담당 문서만 갱신하며 과거 과정과 완료 Spec은 기본 Context에서 제외한다. 확인하지 않은 상태·절감률을 단정하지 않는다.
