# 달마루 문서 관리 기준

## 1. 목적과 적용 범위

이 문서는 달마루의 기획·게임·제작·기술 문서를 공식 기준 문서로 운영하기 위한 분류, 효력, 변경 및 검토 기준을 정한다. `docs/archive/`는 보존 기록이며, 현재 요구사항 또는 구현 근거로 사용하지 않는다.

문서에 적힌 의도는 설계 기준이고, 실제 동작은 코드와 시험 결과가 기준이다. 둘이 다르면 차이·영향·결정 책임자를 기록한 뒤 관련 기준 문서만 갱신한다.

## 2. 문서 상태와 효력

| 상태 | 의미 | 사용 방식 |
|---|---|---|
| 기준 | 현재 결정된 요구·규칙·계약 | 구현·시험·리뷰의 판정 근거 |
| 시험 기준 | 공개 시험에서 사용하는 범위·수치·절차 | 해당 콘텐츠 버전과 함께 적용 |
| 작업 지침 | 제작 과정·인계·문서 관리 방법 | 산출물 작성과 검토의 기준 |
| 작업 명세 | 특정 단계의 한시적 목표 | 완료 뒤 결정 사항을 기준 문서에 이관 |
| 현황·증적 | 현재 구현 상태 또는 시험 결과 | 완료 주장과 다음 작업의 근거 |
| 보존 | 과거 기록 | 참고만 가능, 현재 기준으로 사용 금지 |

## 4. 우선순위와 충돌 처리

1. 실제 동작은 코드와 재현 가능한 시험 증거를 따른다.
2. 요구 범위와 완료 조건은 PRD-001을 따른다.
3. 게임 규칙은 GDD·RUL 문서, 데이터 형식과 저장 경계는 DSD·DCD 문서를 따른다.
4. 시험 수치는 CTS-001의 지정 콘텐츠 버전에서만 우선한다.
5. 작업 명세·현황 문서는 장기 기준 문서를 대체할 수 없다.

동일 주제의 기준 문서가 충돌하면 구현자는 임의로 합치지 않는다. 충돌 위치, 영향 요구사항 ID, 선택지, 최종 결정을 기록하고 책임자가 승인한 정본만 수정한다.

## 5. 변경·검토·승인

- 모든 규칙·수치·계약 변경은 영향받는 요구사항 ID와 관련 문서를 함께 기록한다.
- 저장·경제·소유권·통신 변경은 멱등성, 권한, 장애 복구 및 회귀 검증 범위를 명시한다.
- 시험 수치 변경은 `contentVersion`을 올리고, 기존 공략에는 시작 당시 버전을 보존한다.
- 구현 완료 표시는 PROGRESS와 TEST_RESULT의 증거로만 한다. 설계 문서에 완료 여부를 추정해 적지 않는다.
- 기준 문서의 발행·개정 승인은 프로젝트 책임자가 하며, 구현 담당자는 코드·시험 증거와 변경 제안을 제공한다.

## 6. 문서 작성 최소 요건

기준·시험 문서는 목적, 적용 범위, 규칙 또는 계약, 예외·경계, 관련 요구사항 또는 참조를 포함한다. 표의 수치는 단위·조건·적용 범위를 명시하고, 예시는 규칙을 대체하지 않는다. ID, 시간, 버전, 금액·확률은 기계적으로 판정 가능한 형식으로 쓴다.
