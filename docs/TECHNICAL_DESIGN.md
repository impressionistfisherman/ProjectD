# 달마루 기술 구성·저장 설계


## 1. 개발 환경

시험 기준은 **Minecraft Java Edition 26.1.2 + Fabric + Java 25 + PostgreSQL 18 계열**로 선정한다. 전용 RPG 모드와 리소스팩을 클라이언트에 배포하고, 같은 프로토콜의 전용 서버 모드가 판정·저장을 담당한다.

| 후보 | 장점 | 이 프로젝트의 부담 | 결정 |
|---|---|---|---|
| Fabric 자체 모드 | 전용 키·화면·아이템·통신을 직접 설계 | RPG 기능 대부분 자체 개발, 콘텐츠 도구 필요 | 선정 |
| NeoForge 자체 모드 | 다른 모드 생태계를 활용할 대안 | 필요한 외부 모드 목록이 아직 없어 선택 근거 부족 | 대안 보관 |
| Paper 플러그인 중심 | 서버 플러그인 활용 | 이미 합의한 전용 클라이언트 조작·화면과 추가 통합 필요 | 현재 기준에서 제외 |

전용 입력과 RPG 화면을 자체 제작하는 구성에 맞춰 Fabric을 사용한다. Minecraft 26.1.2와 해당 버전의 공식 문서를 기준으로 개발 환경을 고정한다.

## 2. 구성 요소

| 요소 | 사용 범위 | 적용 시 고려 사항 |
|---|---|---|
| Minecraft | Java Edition 26.1.2 | 버전별 문서를 사용해 구현 |
| Java | JDK 25 | 클라이언트·서버·빌드 환경의 Java 버전 일치 |
| Fabric Loader | 0.19.5 | 첫 기동 시험 뒤 잠금 파일과 함께 고정 |
| Fabric API | 0.155.2+26.1.2 | Loader와 함께 전용 서버 기동 확인 |
| Fabric Loom | 1.17.21 | Wrapper·플러그인을 함께 고정 |
| Gradle Wrapper | 9.7.1 | 프로젝트 생성 뒤 Wrapper 검증 |
| PostgreSQL | 18.6 | 거래·물품 저장과 장애 복구에 사용 |
| PostgreSQL JDBC | 실제 기동 시험에서 Java 25·PostgreSQL 18.6 호환 버전 고정 | 연결·재시작 시험 뒤 잠금 |
| 테스트 | 순수 Java 단위 시험 + 실제 PostgreSQL 통합 시험 + 전용 서버 수동 시험 | 프레임워크 버전은 기초 기동 단계에서 선정 |

Java의 정확한 배포판·패치 버전과 PostgreSQL JDBC 버전은 실제 빈 모드 빌드, 전용 서버 기동, DB 연결·재시작 시험을 통과한 조합으로 잠근다. Minecraft/Loader/API/Loom/Gradle/JDK/JDBC/DB의 배포 파일 해시와 라이선스는 하나의 버전 명세에 기록하고, 배포에는 그 잠긴 버전만 사용한다.

26.1은 비난독화 전환과 Java 25 요구가 있는 경계이다. 1.21.11 이하의 모드를 그대로 복사해 사용할 수 있다고 가정하지 않는다.
외부 애니메이션·NPC·퀘스트·전투 모드는 이번에 필수 의존성으로 지정하지 않는다. 필요 시 공식 배포처에서 해당 게임 버전·로더·클라이언트/서버 측·재배포 조건을 확인해 추가한다.

## 3. 개발·배포 구조

한 저장소, 하나의 게임 서버 프로세스, 하나의 데이터베이스로 시작한다. 다중 서버·프록시·Redis·마이크로서비스는 첫 시험 범위에 포함하지 않는다.

코드는 다음과 같이 게임 규칙, 모드 연동, 콘텐츠, 데이터베이스, 시각 자료와 시험으로 나누어 관리한다.

```text
server-project/
  game-rules/           # Minecraft 의존 없는 수치·조건·확률·경제 규칙
  rpg-mod/
    src/main/           # 서버 판정, 공통 정의, 프로토콜
    src/client/         # 화면, 입력, 렌더링, 음향
  content/              # 직업·스킬·장비·퀘스트·보상·던전 정의
  database/             # 순서가 있는 스키마 변경·복구 자료
  assets/               # 한국어 번역, 모델, 텍스처, 소리
  tests/                # 통합·장애·멀티플레이 검증 자료
  docs/                 # 승인 설계·버전 명세·운영 절차
```

순수 규칙과 게임 연동을 분리하되, 기능마다 별도 서비스로 분산시키지 않는다. Java 25를 기본 언어로 사용한다.

개발은 Windows+PowerShell 기준이다. Fabric 개발 파일은 공백·한글·클라우드 동기화 경로를 피한 영문 경로, 예를 들어 `C:\Projects\dalmaru`에 GitHub 저장소를 복제해 둔다. 현재 `프로젝트달마루` 폴더는 문서와 Git 원격 동기화의 기준으로 유지하며 자동 이동하지 않는다.

시험 운영의 잠정 호스팅 기준은 Linux x86_64, 8 vCPU, 메모리 16GiB, NVMe 100GiB 이상이다. 목표는 동시 접속 20명, 동시 일반 던전 4개, 1분 평균 TPS 19.5 이상, 95% 틱 45ms 이하로 둔다. 이는 시작 예산·부하 시험의 기준이며 실제 공개 수용 인원을 보장하는 값은 아니다.

## 4. 기능별 책임

| 영역 | 서버 책임 | 클라이언트 책임 |
|---|---|---|
| 계정·캐릭터 | 인증 계정 UUID, 접속 잠금, 캐릭터 권한 | 캐릭터 선택·삭제 안내 |
| 전투 | 위치·대상·자원·쿨다운·피해·부활 검증 | 입력 의도 전송·예고·남은 시간 표시 |
| 성장 | 경험치·배분·전직 조건·장비 능력치 계산 | 투자 예상값·추천 안내 |
| 공략 | 명단·난이도·기믹·보상·클리어 예약 | 준비 확인·공략 정보·사망 화면 |
| 경제 | 잔액·소유권·입찰·확률 결과·제작 | 요청·결과·실제 성공률 표시 |
| 콘텐츠 | 정의 검증·조건 평가·버전 고정 | 텍스트·모델·연출 표시 |

클라이언트가 전달한 피해량·성공 여부·가격·귀속·보상 자격을 신뢰하지 않는다. 요청에는 인증된 연결의 계정과 서버 측 활성 캐릭터를 연결하고, 다른 캐릭터 ID를 보내도 권한이 생기지 않게 한다.
입력 빈도·순번·거리·충돌·시야·현재 상태를 검사한다. 전용 모드 설치는 부정행위 방지의 충분조건이 아니다.
클라이언트의 화면·예상 결과는 미리 그릴 수 있지만 재화·물품의 확정 성공 표시는 서버 저장 완료 이후에만 한다.

## 5. 주요 데이터와 불변 조건

| 데이터 | 주요 식별·조건 |
|---|---|
| accounts / characters | 계정 UUID와 별도 캐릭터 UUID, 활성 캐릭터 하나 |
| item_instances | 개별 장비 UUID, 소유 계정·캐릭터·위치·버전·귀속 |
| item_stacks | 재료 종류·수량·위치, 분할/병합 시 수량 보존 |
| wallets / ledger | 정수 재화, 음수 금지, 입출금 원장·사유 |
| operations | 고유 요청 번호, 요청 내용 해시, 확정 결과 |
| run_instances / participants | 고정 명단·버전·난이도·시작 주기·부활 횟수 |
| clear_reservations | 캐릭터·콘텐츠·난이도·주기별 예약/완료 |
| auctions / holds | 최고 입찰·예약 잔액·자격·마감·정산 상태 |
| mailbox / outbox | 미수령 소유권·서버 화면 반영 대기 |
| quest_progress / crafting_orders | 개인 진행·보상 수령·재료 잠금·완성품 |

중요 조건:
- 개별 장비는 하나의 위치와 소유자만 가진다. 재료는 수량 보존으로 검증한다.
- 동일 요청 번호로 다른 내용을 보내면 거부한다. 같은 내용 재요청은 저장된 결과를 반환한다.
- 계정 접속 잠금에는 세대 번호를 두어 끊긴 옛 연결이 재접속 뒤 쓰기하지 못하게 한다.
- 난이도별 횟수 예약과 성공 확정은 동시 실행에서도 한도를 넘지 않는다.
- 입찰 가능액은 소지액에서 다른 예약액을 뺀 금액이다.
- 클리어 인정·보상 소유권·특별 경매 생성은 같은 확정 작업이다.
- 플레이어 이름 변경을 계정 변경으로 취급하지 않는다. 인증 UUID를 사용한다.

## 6. 거래와 게임 월드 사이의 저장 경계

PostgreSQL 트랜잭션은 DB 내부의 원자성을 제공한다. Minecraft 월드 파일·플레이어 NBT와 DB를 자동으로 한 번에 저장해 주지는 않는다.

권장 방식:
1. 게임 서버에서 요청을 검증하고 관련 경제 자원을 처리 중 상태로 잠근다.
2. DB 트랜잭션에서 잔액·물품 위치·실패 보정·처리 결과·반영 이벤트를 함께 저장한다.
3. 저장이 확정되면 서버 스레드에서 가방·화면에 결과를 반영한다.
4. 반영 중 중단되면 재접속 때 DB의 소유권과 미반영 이벤트로 재구성한다.

DB가 경제·장비의 기준 원본이며 화면과 플레이어 가방은 그 결과를 반영한다. 월드 파일을 과거로 되돌렸다고 DB 물품을 다시 발급하지 않는다.
강화 결과는 성공/실패와 비용·귀속·누적 확률을 같이 기록한다. 결과가 확정된 요청은 재추첨하지 않는다. DB 확정 이전의 추첨값은 사용자에게 노출하지 않는다.
메인 틱에서 동기 DB 대기를 하지 않는다. 반대로 비동기 작업 스레드에서 게임 월드를 직접 수정하지 않는다.
DB 장애가 확인되면 경제·보상·제작·거래·강화·캐릭터 전환과 새 공략 시작을 즉시 거부하고 성공으로 표시하지 않는다. 진행 중 공략은 정지 상태로 전환해 최대 5분 동안 DB 복구를 기다리며, 복구하지 못하면 클리어 없이 취소하고 예약을 해제한다. 필드 전투는 진행할 수 있지만 보상·퀘스트 완료처럼 영구 저장이 필요한 결과는 확정하지 않는다.

## 7. 바닐라 기능과의 경계

커스텀 9칸 장비·능력치를 바닐라 방어구·인챈트에 중복 적용하지 않는다. 플레이어 NBT는 RPG 캐릭터의 유일한 원본으로 사용하지 않는다.
첫 시험에서는 RPG 장비의 일반 투척·호퍼·바닐라 상자·모루·제작대·사망 드롭 경로를 제한한다. 허용하려면 같은 소유권·귀속·수량 검증을 통과시키는 전용 경로가 필요하다.
주무기 변경과 능력치 계산은 서버에서 수행한다. 전직 시 이전 캐릭터의 장비·엔더 상자·경험치 등 바닐라 상태가 다른 캐릭터로 섞이지 않도록 관리 대상을 명시한다.

## 8. 던전 인스턴스

첫 시험은 전용 던전 차원에 사전 준비한 복제 구역을 할당하는 방식을 추천한다. 실행 중 차원을 무제한 생성하는 방식은 사용하지 않는다.
- 공략 UUID와 전용 구역을 연결하고 다른 공략의 개체·장치·투사체 접근 금지.
- 출입·귀환·갈고리·축지·블록 설치/파괴를 경계 규칙으로 검사.
- 구역 준비 완료 후 참가자 이동. 종료 후 잔여 개체·드롭·장치·블록 복구 완료 뒤 재사용.
- 동시 공략 한도와 대기열은 부하 시험으로 결정.
- 서버 장애 시 미완료 공략 취소·예약 해제·기록된 소모품 보상. 전투 한 프레임을 완벽 재현하려 하지 않음.
- 클리어 확정 공략은 취소하지 않고 미지급 보상만 재처리.

인스턴스 생성·정리, 전원 접속 종료 정지, 재접속 잔류 개체는 기동 검증 후 별도 구현 실험이 필요하다.

## 9. 시간·정의 버전

영구 시각은 UTC, 초기화 주기는 Asia/Seoul로 계산한다. 기간은 시작 포함/끝 제외. 부활·방어 판정은 서버가 관리하며 단순 클라이언트 시계로 확정하지 않는다.
수치와 퀘스트는 JSON 등 데이터 정의로 관리한다. 화면 이름과 별개로 불변 ID를 둔다.
정의 검사: 중복 ID, 존재하지 않는 스킬·아이템 참조, 순환 선행 조건, 음수 비용, 확률 범위, 직업당 스킬 수, 무기 호환, 인원별 수행 가능 여부.
공략은 시작 당시 콘텐츠 버전에 고정한다. 진행 중 밸런스 파일을 바꿔 같은 공략의 규칙을 교체하지 않는다.

## 10. 복구·운영

- 계정 캐릭터 전환은 마을·비전투, 저장·거래 완료 후 수행.
- 삭제 복구 유예7일. 삭제 후 복원해도 무료 초기화·클리어 횟수 기록 보존.
- 중요 보상 보관함은 직접 입고 불가, 초기에는 자동 소멸 없음.
- 운영자의 지급·회수도 사유·원장·멱등 요청으로 처리.
- DB 기본 백업+연속 WAL 보관, 월드 템플릿·콘텐츠·설정 백업 병행. 별도 장애 영역에 보관.
- DB 시점 복구와 월드 복구 버전을 함께 기록. 개별 캐릭터 전체를 임의로 롤백해 다른 계정의 거래와 충돌시키지 않음.
- 시험 운영의 복구 목표는 일반 서버 재시작 RTO 30분 이내, 전체 호스트 장애 RPO 5분 이내다. 일일 기본 백업, 원격 WAL 보관, 배포 전 월드·콘텐츠 백업을 수행한다. 무손실을 검증 없이 약속하지 않음.

- [Fabric 프로젝트 생성](https://docs.fabricmc.net/26.1.2/develop/getting-started/creating-a-project): 초기 프로젝트 생성 기준.
- [Fabric 26.1 안내](https://www.fabricmc.net/2026/03/14/261.html): Java 25·비난독화 전환, 구버전 모드 호환 경계.
- [Fabric Loader 0.19.5](https://maven.fabricmc.net/net/fabricmc/fabric-loader/0.19.5/): 시험 기준 Loader 배포본.
- [Fabric API 0.155.2+26.1.2](https://maven.fabricmc.net/net/fabricmc/fabric-api/fabric-api/0.155.2%2B26.1.2/): 시험 기준 API 배포본.
- [Fabric Loom 1.17.21](https://maven.fabricmc.net/fabric-loom/fabric-loom.gradle.plugin/1.17.21/): 시험 기준 빌드 플러그인 배포본.
- [Gradle 9.7.1](https://gradle.org/releases/): 시험 기준 Wrapper 버전.
- [Fabric 네트워킹](https://docs.fabricmc.net/develop/networking): 클라이언트·서버 통신 개념. 이 일반 링크의 버전은 변할 수 있어 구현 시 26.1.2 문서 선택 필요.
- [NeoForge 시작 안내](https://docs.neoforged.net/docs/gettingstarted/): 대안 도구 비교.
- [PostgreSQL 18.6](https://www.postgresql.org/docs/release/18.6/): 시험 기준 DB 패치 버전.
- [PostgreSQL 트랜잭션](https://www.postgresql.org/docs/18/tutorial-transactions.html): DB 작업의 원자적 처리.
- [PostgreSQL 연속 보관·시점 복구](https://www.postgresql.org/docs/18/continuous-archiving.html): 기본 백업과 WAL의 복구 조건.

공식 자료는 도구의 기능·요구 조건 근거이며, 본 게임 구현의 호환성·성능을 증명하지 않는다.
