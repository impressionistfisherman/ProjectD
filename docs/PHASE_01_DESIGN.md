# 달마루 — 첫 연결 설계

## 목표와 범위

클라이언트와 전용 서버가 각각 실행되고, 서로 호환되는 달마루 모드인지 확인한 뒤 작은 안내 화면에서 서버 응답을 확인한다. 이 문서는 첫 구현 범위를 제안한다. 기능과 수치는 아래 범위에서 검토하며, 아직 구현·실행으로 검증하지 않았다.

캐릭터 생성·저장, 전투, 재화, 던전, 데이터베이스 연결은 다음 단계로 둔다. 이번에는 기초 연결의 오류를 다른 게임 기능과 분리해서 확인한다.

기존 기술 선택은 [기술 설계의 개발 환경](TECHNICAL_DESIGN.md#1-개발-환경)을 따른다. 해당 문서의 버전은 기존 설계이며 이번 작업에서 호환성을 재검증하지 않았다. Codex는 착수 시 실제 저장소와 기존 구현을 먼저 확인하고, 공식 자료와 빌드·기동 결과로 정확한 의존성 조합을 기록한다. 버전 변경이 필요하면 이유와 영향을 제시한다.

## 구성과 책임

| 구성 | 책임 |
|---|---|
| 공통 정의 | 통신 버전, 메시지 필드와 제약, 오류 코드 |
| 서버 | 연결별 호환성 판정, 요청 제한, 응답 생성, 연결 해제 시 정보 정리 |
| 클라이언트 | 입력과 안내 화면, 응답 대기·오류 표시, 이전 연결의 화면 정보 제거 |

공통·서버 코드는 클라이언트 화면·입력 클래스를 참조하지 않는다. 모듈과 패키지의 실제 배치는 Codex가 기존 저장소에 맞춰 결정한다. 빈 하위 프로젝트를 미리 만들 필요는 없다.

## 접속과 화면

1. 연결마다 새 호환성 확인을 수행한다. 게임 버전과 모드 통신 버전은 별도로 검사한다.
2. 통신 버전이 같으면 서버가 연결을 허용한다. 모드가 없거나 버전이 다르면 이유를 표시하고 연결을 종료한다.
3. 호환성 확인 제한 시간은 10초로 제안한다. 구현 시 선택한 로더의 연결 단계에 맞춰 시작 지점을 기록한다.
4. 접속 후 변경 가능한 전용 단축키로 ‘달마루’ 안내 화면을 연다. 기본 키는 기존 키 설정과 충돌 여부를 확인해 Codex가 선택한다.
5. 화면의 ‘연결 확인’을 누르면 서버 응답을 요청한다. 대기 중에는 중복 클릭을 막고, 5초 동안 응답이 없으면 다시 시도할 수 있는 오류를 표시한다.
6. 채팅이나 다른 입력 화면에서 단축키를 눌러도 안내 화면이 열리지 않는다. 이번 키는 향후 전투 키와 별개다.

## 통신과 임시 데이터

아래 이름은 논리적 메시지 이름이다. 패킷 등록 방식과 직렬화 API는 선택한 개발 환경에 맞춰 구현한다. JSON 패킷을 필수로 요구하지 않는다.

| 메시지 | 방향 | 필드·제약 |
|---|---|---|
| Hello | 클라이언트 → 서버 | protocolVersion: 양의 정수, 첫 버전 1 |
| Welcome | 서버 → 클라이언트 | protocolVersion: 1; 호환성 확인 성공 때 한 번 |
| ProbeRequest | 클라이언트 → 서버 | requestId: 연결 안에서 증가하는 양의 64비트 정수 |
| ProbeResponse | 서버 → 클라이언트 | requestId: 요청과 동일, result: OK 또는 RATE_LIMITED |

서버는 연결에서 플레이어를 식별한다. 요청에 계정·캐릭터 ID를 넣지 않는다. 호환성 확인 전 ProbeRequest는 거부한다. 필드 형식과 범위를 벗어난 요청은 연결을 종료하고 원인을 기록한다.

서버는 연결별로 초당 한 번의 ProbeRequest만 허용한다. 제한된 요청은 RATE_LIMITED로 응답하되, 제한 응답도 초당 한 번으로 제한하고 추가 요청은 무시한다. 클라이언트 클릭 제한과 서버 요청 제한을 각각 적용한다.

연결별 임시 정보는 호환성 확인 여부와 요청 제한 시각이며, 영구 저장하지 않는다. 클라이언트는 현재 요청 번호와 대기 여부를 보관한다. 시간 초과 이후 또는 이전 요청 번호의 응답은 화면에 반영하지 않는다. 연결 종료 시 모두 폐기하고 재접속은 새 연결로 처리한다.

이 요청은 게임 데이터 변경이 없는 연결 확인용이다. 이후 재화·아이템 변경 요청은 기술 설계의 저장·중복 처리 규칙을 별도로 적용한다.

## 완료 조건과 시험

| 항목 | 확인할 결과 |
|---|---|
| 재현 가능한 빌드 | 고정된 의존성·실행 명령을 기록하고 동일 소스에서 빌드 성공 |
| 전용 서버 실행 | 그래픽 환경 없이 기동하며 클라이언트 전용 클래스 로딩 오류 없음 |
| 정상 연결 | 동일 통신 버전의 클라이언트가 접속하고 연결 확인 응답 표시 |
| 호환성 실패 | 모드 없음·통신 버전 불일치·확인 시간 초과를 각각 거부 |
| 입력 | 키 변경 반영, 채팅 중 오작동 없음, 대기 중 중복 클릭 방지 |
| 응답 오류 | 5초 시간 초과 후 재시도 가능, 늦은 응답이 새 요청을 덮어쓰지 않음 |
| 잘못된 요청 | 형식·범위 위반, 확인 전 요청, 연속 요청이 정해진 규칙대로 처리됨 |
| 두 사용자·재접속 | 응답과 요청 제한이 연결별로 독립적이며 재접속 후 이전 정보가 남지 않음 |

버전 판정·시간 경계·요청 제한은 가능한 범위에서 자동 시험하고, 실제 전용 서버와 클라이언트에서 연결·화면을 확인한다. 미실행 항목은 이유와 함께 남긴다. 빌드 성공만으로 화면과 멀티플레이 시험까지 통과했다고 처리하지 않는다.

## 다음 단계로의 연결

위 조건을 구현 증거로 확인한 다음 계정·캐릭터 선택과 저장을 설계한다. 그때 연결별 호환성 확인 위에 활성 캐릭터와 저장 권한을 연결한다. 이번 임시 요청 번호를 영구 거래 식별자로 재사용하지 않는다.

구현 인계 전 실제 저장소 경로와 기존 구현 여부를 확인해야 한다. 이 설계 폴더에는 게임 코드가 없으며 별도 구현 작업의 최신 상태는 여기서 확인하지 않았다.
